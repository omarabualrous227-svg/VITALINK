# VITALINK 2076 — الحزمة الكاملة للمشروع

**النسخة:** v3.0 Backend Multi-Device  
**نوع المشروع:** MVP تجريبي لتنسيق الطوارئ ودعم قرار اختيار المستشفى  
**الفرونت إند:** نسخة v30 الأصلية، محفوظة دون أي تعديل

## محتويات الحزمة
- `public/index.html` — الفرونت إند الذي يخدمه السيرفر، مطابق بايت-ببايت للملف الأصلي.
- `frontend/VITALINK_Irbid_MVP_v30_BackendAware.html` — نسخة مستقلة من نفس الفرونت إند، ومطابقة للملف الذي يخدمه السيرفر.
- `server.js` — Backend باستخدام Node.js وExpress وWebSocket.
- `server-lite.js` — نسخة بديلة بدون حزم خارجية، وتعتمد على Node.js 22.5+.
- `db.js` — إدارة SQLite وحالة المزامنة وسجل الأحداث.
- `tests/integration.mjs` — اختبارات تكامل للـBackend.
- `dataset/` — ملفات JSON وCSV للداتا سيت التجريبية: المستشفيات، وحدات الإسعاف، السيناريوهات، والحالات التجريبية.
- `scripts/seed-demo-state.js` — أداة اختيارية لتحميل بيانات المستشفيات التجريبية إلى SQLite.
- `BACKEND_QA_REPORT.txt` — تقرير الاختبارات وحدود بيئة الاختبار.

## تشغيل المشروع على Windows
1. فك ضغط الملف كاملًا إلى مجلد.
2. ثبّت Node.js إصدار 22.5 أو أحدث.
3. شغّل `START_VITALINK_WINDOWS.bat`.
4. افتح `http://localhost:8080` إذا لم يفتح المتصفح تلقائيًا.
5. اترك نافذة السيرفر مفتوحة أثناء التجربة.

إذا تعذّر تثبيت حزم npm أو لم تتوفر الشبكة، جرّب `START_VITALINK_LITE_WINDOWS.bat`. هذه النسخة لا تحتاج إلى تثبيت Express أو ws، لكنها تحتاج Node.js 22.5+.

## واجهات الأدوار
- المريض: `http://localhost:8080/?role=patient`
- مركز 911: `http://localhost:8080/?role=dispatch`
- الإسعاف EMS: `http://localhost:8080/?role=ems`
- المستشفى: `http://localhost:8080/?role=hospital`

للتجربة على أكثر من جهاز ضمن نفس الشبكة، شغّل السيرفر على جهاز واحد وافتح عنوان الـLAN IP الخاص به من بقية الأجهزة، مع بقاء الأجهزة على نفس الشبكة. مثال الصيغة: `http://SERVER-LAN-IP:8080/?role=ems`.

## تحميل الداتا سيت إلى SQLite (اختياري)
إذا بدك تبدأ بالحالة التجريبية الموجودة في ملف الداتا سيت:

```bash
node scripts/seed-demo-state.js
```

الأداة لا تستبدل حالة موجودة تلقائيًا. إذا كانت قاعدة البيانات تحتوي حالة بالفعل، ستتوقف دون تغييرها.

للاستبدال المتعمد للحالة المشتركة الحالية:

```bash
node scripts/seed-demo-state.js --force
```

هذا الخيار يستبدل الحالة المشتركة الحالية ويضيف حدثًا جديدًا لسجل التدقيق، لكنه لا يحذف الأحداث القديمة. خذ نسخة احتياطية من قاعدة البيانات أولًا إذا كانت الحالة الحالية مهمة.

## ملاحظات مهمة
- ملفات الفرونت إند والباك إند الأصلية من حزمة v30 محفوظة كما هي؛ الإضافات الجديدة موجودة بملفات منفصلة.
- الداتا سيت تجريبية وليست بيانات تشغيلية حقيقية. الأرقام الخاصة بالأسرة والضغط والجاهزية والمسافة ووقت الوصول أمثلة فقط.
- النظام لا يشخّص المرض ولا يوجّه سيارات الإسعاف بشكل مستقل.
- لا يوجد حاليًا تسجيل دخول أو صلاحيات RBAC؛ لا تنشر النسخة مباشرة على الإنترنت العام.
- لا تستخدم بيانات مرضى حقيقية.
- الخريطة وسياق الاتجاهات خارجيان؛ لا توجد بيانات مرور مباشرة.
- قاعدة SQLite تنشأ تلقائيًا داخل `data/` عند التشغيل، ولا تتضمن الحزمة قاعدة بيانات تشغيلية قديمة.

## فحص سلامة الفرونت إند
الملف الأصلي والنسختان الموجودتان داخل الحزمة متطابقة في المحتوى. راجع `INTEGRITY_MANIFEST.txt` للتحقق من بصمة SHA-256.
